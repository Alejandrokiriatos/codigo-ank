================================================================
1. OBJETIVO GENERAL DEL PROYECTO
================================================================

Transformar Código ANK para eliminar la dependencia de OpenCode y permitir que cualquier usuario conecte proveedores de inteligencia artificial mediante sus propias API. La aplicación debe servir como entorno de trabajo donde distintos modelos/proveedores puedan operar dentro del proyecto, manteniendo una experiencia coherente tanto en móvil como en escritorio.

El desarrollo debe continuar sobre la rama ank/block-3-multiple-api. No trabajar directamente sobre main ni mezclar este trabajo con la rama principal sin una revisión y autorización explícitas.

================================================================
2. TRABAJO REALIZADO HASTA AHORA
================================================================

A. Sustitución de OpenCode y motor multi-API
- Se implementó una arquitectura de proveedores API para sustituir el flujo dependiente de OpenCode.
- Se contemplan proveedores compatibles con OpenAI, Anthropic y Gemini.
- También se contempla configuración JSON personalizada para APIs compatibles o adaptadores específicos.
- El diseño admite hasta 12 conexiones/configuraciones de proveedor.
- La intención es que cada usuario pueda introducir sus propios datos de conexión y seleccionar el proveedor/modelo que utilizará.

B. Protección y persistencia de credenciales
- Se implementó almacenamiento cifrado apoyado en Android Keystore y EncryptedSharedPreferences.
- Se trabajó en la migración de la configuración existente al nuevo sistema.
- La revisión debe confirmar en un dispositivo real que las claves sobreviven al cierre/reinicio y que no aparecen en registros, interfaz, archivos exportados ni mensajes de error.

C. Interfaz y sincronización
- Se realizaron cambios de interfaz para móvil y escritorio relacionados con la nueva configuración multi-API.
- Se sincronizaron cuatro copias de los archivos ai.js y ai.css para evitar divergencias entre las distintas ubicaciones del proyecto.
- La siguiente auditoría debe volver a comparar todas las copias y comprobar que no existan versiones antiguas activas o rutas que carguen archivos equivocados.
